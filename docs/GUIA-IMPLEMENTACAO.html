As instruções de terminal são para Windows / PowerShell. A pasta do projecto tem espaços, por isso as aspas importam. Os dois servidores (backend e frontend) ficam a correr — fecha cada um com Ctrl + C.

Pré-requisitos

Precisas de duas ferramentas instaladas. Confirma as versões no PowerShell:

# Node.js 18 ou superior
node -v
# Docker Desktop (para a base de dados PostgreSQL)
docker -v

Se algum não der versão: Node.js e Docker Desktop. Sem Docker, dá para usar um PostgreSQL instalado localmente (ver nota no Passo 2).

1Base de dados

Numa janela do PowerShell, arranca o PostgreSQL (já no fuso de Lisboa):

cd "<PASTA-DO-PROJECTO>\ticket-system"   # o caminho onde colocou o projecto
docker compose up -d
Fica a correr em segundo plano. Para parar mais tarde: docker compose down (os dados mantêm-se).

2Backend (API)

Na mesma janela:

cd backend
copy .env.example .env       # deixa os MS_* vazios = modo de teste, sem Outlook
npm install
npm run db:reset             # cria tabelas (migrações 001 a 004) + utilizadores
npm run demo                 # gera ~400 tickets de demonstração (ou: npm run demo 800)
npm run dev                  # API em http://localhost:4000
O que cada comando faz: db:reset aplica todas as migrações (incluindo vendas, métricas de tempo e agrupamento de conversas) e cria os perfis de demonstração; demo enche a base com tickets realistas para os relatórios terem dados.
Sem Docker? Cria uma base de dados PostgreSQL local, mete a ligação em DATABASE_URL no backend\.env e corre npm run db:reset. O resto é igual.

3Frontend

Abre uma segunda janela do PowerShell:

cd "<PASTA-DO-PROJECTO>\ticket-system\frontend"
npm install
npm run dev                  # interface em http://localhost:5173

4Entrar e testar

Abre http://localhost:5173 e usa os botões de entrada rápida:

PerfilO que testar
admin@empresa.pt
Administrador		Painel do supervisor; separador Relatórios (períodos, âmbito por cliente/operador/equipa, exportar Excel e PDF).
carlos.fatura@empresa.pt
Operador · Faturação		Fila, Assumir, abrir o detalhe, responder e Resolver.
ines.comercial@empresa.pt
Operador · Comercial		Resolver um ticket Comercial: é obrigatório marcar Ganhou/Perdeu e o valor — alimenta a conversão.

Na fila do operador há o botão "+ Ticket de teste" (só em desenvolvimento) para injectar tickets ao vivo e ver os cronómetros e alertas de SLA. Para limpar os dados de demonstração: npm run demo:clear (na pasta backend).

Checklist rápido: login (admin e operador) · fila em tempo real (abrir 2 separadores) · assumir/resolver · alertas de SLA · Relatórios com filtros · exportar Excel e PDF.

5Ligar o Outlook (Microsoft 365)

Para captar emails reais da caixa partilhada (em vez dos tickets de teste), preenche os MS_* no backend\.env. O passo a passo detalhado (registo no Azure AD, permissões, Application Access Policy, túnel para desenvolvimento) está em docs/INTEGRACAO-GRAPH.md. Resumo:

  • Registar a aplicação no Microsoft Entra ID (Azure AD) e copiar MS_TENANT_ID, MS_CLIENT_ID, MS_CLIENT_SECRET.
  • Permissões de aplicação com consentimento de admin: Mail.Read, Mail.Send.
  • Restringir a app à caixa certa com uma Application Access Policy.
  • Definir MS_SHARED_MAILBOX e MS_WEBHOOK_URL (URL pública HTTPS; em dev usar um túnel como o ngrok).
A associação dos emails ao ticket usa o identificador interno da mensagem e o conversationId da conversa — não depende do assunto. Respostas do cliente à mesma conversa juntam-se ao ticket aberto; uma resposta a um ticket já resolvido abre um ticket novo.

6Integração com sistema externo (vendas)

Hoje o operador marca a venda à mão ao resolver. Para preencher o valor da venda automaticamente a partir do vosso sistema de reservas/faturação, a app expõe um endpoint seguro. Quando uma reserva é confirmada/faturada, o sistema externo chama este endpoint e o ticket fica com o resultado e o valor — e os relatórios actualizam-se sozinhos.

6.1 Activar a integração

Gera uma chave forte e coloca-a no backend\.env. Enquanto estiver vazia, o endpoint está desactivado.

# gerar uma chave aleatória (exemplo)
openssl rand -hex 32
# em backend\.env
INTEGRACAO_API_KEY=cole_aqui_a_chave_gerada
Trata a chave como uma palavra-passe: só no servidor e no sistema externo, nunca no frontend nem em repositórios públicos. Em produção, o endpoint deve ser sempre HTTPS.

6.2 Registar a venda — POST /api/integracoes/venda

Cabeçalhos: Content-Type: application/json e x-api-key: {A_SUA_CHAVE}.

No corpo, envia uma referência ao ticket + o resultado:

CampoDescrição
ticketIdId do ticket (UUID). A referência mais fiável, se a guardarem na reserva.
conversationIdId da conversa do Outlook (atualiza o ticket mais recente dessa conversa).
outlookMessageIdId da mensagem original do email.
resultadoganho · perdido · nao_aplicavel (obrigatório).
valorValor da venda em euros (só conta quando ganho).

Exemplo (PowerShell):

curl.exe -X POST "https://tickets.suaempresa.pt/api/integracoes/venda" `
  -H "Content-Type: application/json" `
  -H "x-api-key: A_SUA_CHAVE" `
  -d '{ "conversationId": "AAQkAGI2...", "resultado": "ganho", "valor": 1850.00 }'

Resposta:

{ "ok": true, "ticket": { "id": "8f3...", "resultado_venda": "ganho", "valor_venda": 1850.00 } }

6.3 Registar emissões — POST /api/integracoes/emissao

Para medir a precisão de emissão, o sistema de reservas/emissão reporta quantos bilhetes/vouchers foram emitidos no ticket e quantos saíram com erro (obrigaram a reemissão). Mesmo cabeçalho x-api-key.

CampoDescrição
ticketId / conversationId / outlookMessageIdUma referência ao ticket (igual ao endpoint de venda).
emitidosNº total de bilhetes/vouchers emitidos (inteiro ≥ 0, obrigatório).
comErroNº desses que saíram com erro (inteiro ≥ 0; é limitado automaticamente a ≤ emitidos).
curl.exe -X POST "https://tickets.suaempresa.pt/api/integracoes/emissao" `
  -H "x-api-key: A_SUA_CHAVE" -H "Content-Type: application/json" `
  -d '{ "conversationId": "AAQkAGI2...", "emitidos": 3, "comErro": 0 }'

Resposta:

{ "ok": true, "ticket": { "id": "8f3...", "bilhetes_emitidos": 3, "bilhetes_com_erro": 0 } }

A precisão de emissão nos relatórios = 1 − (bilhetes com erro ÷ bilhetes emitidos), agregada por operador e por equipa.

6.4 Consultar um ticket — GET /api/integracoes/ticket

Para o sistema externo confirmar o alvo antes de gravar: /api/integracoes/ticket?conversationId=AAQk... (ou ?ticketId=...), com o mesmo cabeçalho x-api-key.

6.5 Como ligar os dois sistemas (recomendado)

  • Opção A (mais robusta): quando uma oportunidade nasce de um ticket, guardem o ticketId (ou conversationId) na reserva do sistema externo. Ao fechar a reserva, chamam o endpoint com essa referência. Associação exacta, sem ambiguidade.
  • Opção B: sem referência guardada, usem o conversationId (visível no Outlook) ou o email do cliente + período para localizar o ticket via GET .../ticket e depois gravar.
CódigoSignificado
200Venda registada.
400Falta referência ou resultado inválido.
401Chave de API inválida ou em falta.
404Não há ticket para a referência indicada.
503Integração desactivada (INTEGRACAO_API_KEY não definida).
A marcação manual pelo operador continua a funcionar. A integração apenas a complementa/automatiza — o último valor gravado prevalece.

7Produção

O checklist completo (pré-produção, Caddy+Docker, Azure App Service e smoke test) está em docs/CHECKLIST-DEPLOY.md. Pontos essenciais:

  • NODE_ENV=production e JWT_SECRET longo e aleatório (o arranque é bloqueado se for fraco).
  • TZ=Europe/Lisbon no processo (o SLA depende disto).
  • HTTPS obrigatório e WebSocket activo no reverse-proxy (para o tempo real).
  • Aplicar migrações em produção (npm run migrate) e não correr demo.
  • Substituir os perfis de demonstração por utilizadores reais; idealmente SSO/Entra ID.

Resolução de problemas

SintomaCausa provável / solução
Backend não arranca, erro de base de dadosO PostgreSQL não está a correr (docker compose up -d) ou DATABASE_URL errado.
O arranque bloqueia por causa do JWT_SECRETEm produção o segredo tem de ter ≥32 caracteres e não ser o valor por omissão.
Relatórios vaziosFaltam dados — corre npm run demo (teste) ou aguarda emails reais.
Gráficos não aparecemSem ligação à Internet (Chart.js/SheetJS vêm de CDN). As tabelas continuam a funcionar.
/api/integracoes/venda dá 503Falta definir INTEGRACAO_API_KEY no servidor.
Não chegam emails ao ticketConfiguração do Graph incompleta — ver docs/INTEGRACAO-GRAPH.md.
